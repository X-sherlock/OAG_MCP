# OAG 回答稳定性展示页

这是一个独立静态页面，不依赖当前项目的 Python、Java 或 `ontology_editor` 服务。

## CSV 格式

推荐表头：

```csv
序号,问题,朴素回答,OAG回答
```

- 同一问题的 `序号` 相同。
- 每个序号预期出现 5 行。
- `朴素回答` 和 `OAG回答` 可以是 Markdown 文本。
- 如果 CSV 只有 `序号,朴素回答,OAG回答` 三列，页面仍能导入，但无法展示真实问题文本，也只能按序号和回答内容搜索。
- 页面会自动尝试 UTF-8、GB18030/GBK 等常见中文 CSV 编码。WPS 另存的 CSV 如果不是 UTF-8，页面通常也能读取，但正式迁移和归档仍建议另存为 UTF-8 CSV。

## 使用方式

方式一：直接打开 `index.html`，点击“导入 CSV”选择测试结果文件。

方式二：把真实 CSV 替换为 `data/results.csv`，在本目录启动静态服务：

```powershell
python -m http.server 8020
```

然后访问：

```text
http://127.0.0.1:8020/
```

## 稳定性评分

页面对每个问题分别计算“无 OAG”和“有 OAG”的回答稳定性。评分采用通用文本一致性算法，不依赖金融领域关键词或固定结论规则：

```text
稳定性 = 0.35 * 共识相似
       + 0.20 * 信息覆盖一致性
       + 0.35 * 数值/实体一致性
       + 0.10 * 表达结构一致性
```

共识相似综合 TF-IDF cosine、ROUGE-L、METEOR 式精确率/召回调和、Jaccard/containment 重叠、字符级 Dice 和多数派共识覆盖；信息覆盖按句子、列表项、表格行等信息单元互相匹配，用于展示相似表达；数值/实体一致性只抽取通用数字、百分比、日期、排名、代码等可比较项，用于避免“模板相似但关键数值漂移”被误判为稳定。分数范围是 0-100。`OAG 优势` 为 `有 OAG 稳定性分 - 无 OAG 稳定性分`。

空字符串、`None`、`null`、`NaN`、`undefined`、`无回答`、`未回答` 等会被视为缺失回答。缺失回答按测试环境噪声处理，不参与稳定性评分；页面会保留缺失数量提示。某一侧有效回答少于 2 条时，该侧显示“有效样本不足”，不进入整体平均分。
